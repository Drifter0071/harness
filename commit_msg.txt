fix(chat): persist session on chat-done so reload shows the response

The chat streaming path in llm_client.rs never calls save_session,
so chat-mode responses only lived in the in-memory Zustand store.
On reload, the session was re-read from disk without the new
messages, so the response appeared to vanish.

The store already has a debounced auto-save (scheduleSave via
useProjectLifecycle). chat-done now calls flushPendingSave() to
force the write through immediately instead of waiting for the
500ms debounce window.
